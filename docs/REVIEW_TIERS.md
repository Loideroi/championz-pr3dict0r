# Review Tier Floor Map

Per-repo path→minimum-tier map required by the multi-agent code review contract
(Loideroi LLM Wiki, `agent/contracts/multi-agent-code-review.md`). These are
FLOORS: a touched path sets the minimum tier; the author's declaration or a
reviewer's contest can only raise it, never lower it. Highest applicable tier
wins. Changing THIS file (or the review log) is itself Tier 3 — tier
boundaries belong to the human.

| Path | Tier floor | Why |
|---|---|---|
| `contracts/**` (sources, tests, configs, scripts, lockfile) | 3 | On-chain prediction pools and settlement — value-moving |
| `relayer/**` (incl. its lockfile) | 3 | Oracle relayer — the results it produces settle pools; wrong data is value-moving even when no key is held |
| `.github/workflows/**` | 3 | CI is a merge gate; `oracle-bot.yml` is production automation with repo secrets |
| `supabase/**` (incl. `migrations/**`) | 3 | Production data schema and config — migrations are named Tier 3 in the contract |
| `app/api/**` | 3 | Server-side routes |
| `middleware.ts` and any edge/proxy module owning CSP, geo-restriction, or security-header policy | 3 | Production security enforcement (Fanbet reviewer-finding parity, 2026-08-27) |
| Any module that constructs, signs, or submits chain transactions, and Reown/AppKit wallet configuration (`lib/wagmi/**`, `app/providers.tsx`) | 3 | Signing surface — path-independent catch-all |
| `lib/supabase/**`, `lib/telegram/**`, `lib/profile/verify.ts`, `lib/profile/rate-limit.ts` — and any module handling secrets, privileged service clients, or authentication/signature verification | 3 | Auth/secrets kernel (reviewer finding 2026-08-27): the service-role Supabase client, ERC-1271/EOA wallet verification, and account linking are the contract's "auth, permissions, secrets handling" — path-independent catch-all applies to new modules of this kind |
| `scripts/**` | 3 | `check-i18n-parity.mjs` is gate tooling; catch-all: any script that signs, deploys, or mutates production data is Tier 3 regardless of name |
| `.github/**` (non-workflows), `.npmrc` (all three roots), `eslint.config.mjs`, `.dependency-cruiser.js`, `knip.jsonc`, `.squawk.toml`, `contracts/slither.config.json`, `contracts/slither-triage.json`, `contracts/requirements-slither.in` + `.txt`, `next.config.ts`, `vitest.config.ts`, `tsconfig*.json`, `postcss.config.mjs` | 3 | Guardrail / build / deploy config — editing these can silence a gate. A new `slither-triage.json` entry is an accepted security finding: it needs the exact expression, the reason, and a SECURITY_FINDINGS.md cross-reference in the same PR |
| `package.json`, `contracts/package.json`, `relayer/package.json` | 3 | Own the gate scripts; editing them can silence every gate |
| `package-lock.json`, `contracts/package-lock.json`, `relayer/package-lock.json` | 3 | Precedent: chilitize adjudication 2026-08-25, mirrored on Fanbet with explicit owner confirmation 2026-08-27 (supply chain feeding CI; no reviewer credibly reads a lockfile blob — detection is mechanical or nothing). Deliberately stricter than the contract's Tier 1 dependency-patch row; owner confirmation for this repo recorded at the 2026-08-27 wiring gate |
| `AGENTS.md`, `CLAUDE.md`, `.claude/**`, `docs/REVIEW_TIERS.md`, `docs/REVIEW_LOG.md` | 3 | Agent instruction files and the review process itself |
| `docs/**` (except the two review files above), other `*.md`, comments-only diffs | 1 | Docs / formatting |
| **Anything not listed above** (incl. `app/**` pages, `components/**`, `hooks/**`, `lib/**`, `messages/**`, `content/**`) | 2 | Default floor until mapped — an unlisted path is never Tier 1 by omission; add a row when a new surface appears |

Wired warn-only 2026-08-27; measured again 2026-09-11 before the flip; relayer baseline measured 2026-09-12.

| jscpd (`npm run dup`: app, components, hooks, lib, middleware.ts, relayer/src; tests excluded, min-tokens 50) | 9 exact clones, 0.86% duplicated lines | CI threshold **1%** (tightened from 2% on 2026-09-11) — ratchet down as clones consolidate |

Triage ids embed the source mapping for node-level findings (an edit that moves those lines re-surfaces them) and the canonical variable name for variable-level ones (`uninitialized-local`), so a refresh is a conscious act in the same PR (remove stale entries, add the new ids with reasons) — the database can only shrink or be deliberately refreshed. `show_ignored_findings: true` is mandatory in `slither.config.json` (the gate refuses to run without it): inline `// slither-disable-*` comments cannot hide a finding. Python side hash-pinned since 2026-09-13: CI installs `contracts/requirements-slither.txt` (49 packages, exact versions + sha256 for every published wheel) with `--require-hashes --only-binary=:all:` — see the Named Follow-Up below for the refresh procedure and the residual boundary. A new migration must be squawk-clean; deliberate exceptions land as commented, justified `.squawk.toml` exclusions in the same PR. `npm run migrations:lint` is the full-history debt view (expect exit 1 until history is cleaned) |

- ~~**Slither Python pins**~~ **Done 2026-09-13** (PR #108; named in PR #105 as "hash-pinned Python requirements for slither's transitive dependencies"): the `contracts` job installs `contracts/requirements-slither.txt` — `pip-compile --generate-hashes` output for `contracts/requirements-slither.in` (`slither-analyzer==0.11.4`): 49 packages, each pinned by exact version and by the sha256 of **every** file PyPI publishes for that release (1630 hashes; e.g. cytoolz 173 wheels, pure-Python packages wheel + sdist), so one file serves manylinux x86-64 in CI and macOS locally on CPython 3.11. Install flags: `--require-hashes` (pip refuses any artifact whose hash is absent or differs — proven 2026-09-13 in fresh venvs: a bogus hash list → `THESE PACKAGES DO NOT MATCH THE HASHES`, exit 1; a package with its hashes removed → `Hashes are required in --require-hashes mode`, exit 1) and `--only-binary=:all:` (no sdist builds, so no isolated build environment can fetch unpinned build dependencies; every locked package has a wheel usable on manylinux x86-64 — manylinux-tagged or platform-independent `py3-none-any` — verified with `pip download --only-binary=:all: --platform manylinux2014_x86_64 … --require-hashes`). Resolved on macOS arm64 / CPython 3.11.14; the 211 environment-marker requirements across the locked set were evaluated for linux-x86_64 and darwin-arm64 at Python 3.11 and none differ or point outside the lock — the CI run on Linux is the final proof, and a missing package would fail loudly (pip rejects an unpinned requirement in `--require-hashes` mode) rather than install something unhashed. **Local install (the only documented path, same file):** `python3.11 -m venv .venv && .venv/bin/pip install --require-hashes --only-binary=:all: -r contracts/requirements-slither.txt`, then `npm run slither` in `contracts/` with `.venv/bin` on `PATH`. **How to refresh** (Tier 3; bump the `.in` first; re-triage `slither-triage.json` in the same PR if findings move): from the repo root, `python3.11 -m venv /tmp/pip-tools && /tmp/pip-tools/bin/pip install pip-tools==7.6.1 && CUSTOM_COMPILE_COMMAND="pip-compile --generate-hashes --strip-extras --output-file=contracts/requirements-slither.txt contracts/requirements-slither.in  (pip-tools 7.6.1, CPython 3.11; see docs/REVIEW_TIERS.md)" /tmp/pip-tools/bin/pip-compile --generate-hashes --strip-extras --output-file=contracts/requirements-slither.txt contracts/requirements-slither.in` (pip-tools is a build-time tool in a throwaway venv, never a repo dependency; `CUSTOM_COMPILE_COMMAND` only sets the header — pip-tools 7.6.1 otherwise prints a deprecated `--no-index` alias there). Then repeat the fresh-venv install, `slither --version`, and `npm run slither`. **Residual boundary (not hashed, deliberately):** the interpreter — `actions/setup-python@v5` with `python-version: "3.11"` floats within 3.11.x, like every other action tag in this workflow (pinning actions by commit SHA is a workflow-wide decision, not this PR's) — and pip itself (whatever setup-python bundles; `--require-hashes` semantics have been stable since pip 8). A Python **minor** change (3.12+) is a regenerate, not a config edit. Not added: a `pip` Dependabot ecosystem for this file (a new automation surface — owner decision; the npm ecosystems' 2-day cooldown pattern would apply).
