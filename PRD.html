§1–3

Summary & heritage

Five big evolutions over the World Cup predictor. Everything else is a proven reuse per the predecessor's REUSE_GUIDE.

  1. Two-pronged entry — early birds play the whole season (1,100 CHZ); latecomers join the knockout (550 CHZ).
  2. Hands-off ops — results flow automatically from UEFA's own (unofficial) JSON API. Routine per-match admin work: zero.
  3. Radically cheaper gas — claim-time scoring deletes the O(users × matches) settlement loops.
  4. Community on Telegram — results channel + feedback group + optional account linking.
  5. New look — the "European nights" glow aesthetic, credited to BigMac Bobby in the footer.

Reused from the predecessor

Staking/prediction/claim flow · 5/3/1 scoring + knockout bonuses · 60-min lockout · single-file matches.json (now generated, not hand-authored) · knockout feeder resolution (extended to two-legged ties) · numbering-independent bracket verification (re-pointed FIFA → UEFA) · ERC-1271 dual-path signature verification · Supabase read-model · UUPS upgrade toolchain · the 18-finding audit checklist as regression baseline · all 6 locales at launch (en, es, fr, it, pt-BR, tr — D10; ⚠ 6× content in the August crunch) · AI Match Insights, automated per-matchday (en generation from UEFA data → 5-locale translation via the merge tooling; empty-safe, may lag fixtures — D11).

Deleted

Per-user settlement (batchSettleUserPoints) · in-app feedback (→ Telegram) · hand-authored fixtures · the 512.82-CHZ fee math.

§4 · flagship change

The two-pronged predictor

One season, two stages, two pools, exactly two paying leaderboards — and one cosmetic crown for the end-to-end story.

1,100 CHZ
Full Season pass · hard close at MD1 kickoff (8 Sep 2026)

500 → League Pool · 500 → Knockout Pool · 100 → admin fee. One transaction, both stages, automatically. No late league entry (D1).

550 CHZ
Knockout pass · on sale from MD1 kickoff → T-60 of the last play-off first-leg (~17 Feb 2027)

500 → Knockout Pool · 50 → admin fee. The shop is never closed (D4): September buyers wait as engaged spectators; final-day joiners see exactly which matches are already locked (0 pts) before paying. Non-refundable from purchase.

Why this design

  • Rejected: one leaderboard with a latecomer points-handicap — arbitrary, gameable, every payout contested.
  • Rejected: carrying league points into the knockout — latecomers pay the same 550 CHZ for Stage 2; nobody starts behind in a pool they funded equally.
  • Rejected: a third paying leaderboard — fewer leaderboards, fatter prizes.
  • Fairness invariants: same 550 CHZ per stage for everyone · no points cross a pool boundary · each pool funded only by wallets eligible to win it. Early birds' edge is structural: two shots at prizes + a mid-season payday.

Clean economics: flat 50 CHZ fee per stage to the admin wallet — no more 512.82-style decimals. Contract enforces msg.value == ENTRY_GROSS exactly. Entries non-refundable from purchase. One entry per wallet per stage.

Participation floor (D2): a stage that locks with fewer than 20 entrants is void — everyone reclaims the full 550 CHZ, fee included. At ≥ 20, the top-20 split applies as designed. One number, one rule, one T&C sentence.

§5

Scoring

The proven rubric — now applied to two-legged ties, and always on the 90-minute score.

PredictionPointsCondition
Exact score5both scores exact (90′)
Goal difference3same outcome + same goal difference
Outcome1correct W/D/L only
Extra time · Penalties · Advancing team+1 eachknockout deciders + final only

★ The 90-minute rule (hard requirement)

All scoreline points use the score after 90 minutes, even when the world reports the AET score. The UEFA feed separates these natively: score.regular (90′) vs score.total (incl. ET), plus score.penalty and score.aggregate. Flags derive from winner.match.reason (WIN_ON_EXTRA_TIME, WIN_ON_PENALTIES, …). A real AET match from archive data must pass in CI before mainnet.

Two-legged ties (new vs. the World Cup)

  • Leg 1: normal 5/3/1 on its own 90′ score — no bonuses (a first leg can't go to extra time).
  • Leg 2 (decider): 5/3/1 on its own 90′ score plus the three tie bonuses.
  • Final: single match, all bonuses. Requires a tieId/decider concept in data + resolution engine — its own build slice.

Tie-breaks: points → most exact scores → earliest entry → lowest wallet address ("because computers enjoy order") — canon, preserved.

§6

Editing predictions — a feature, not a loophole

The old contract always allowed overwrites before lockout; the old UI never said so. Now it's front and centre.

  • Editable until 60 minutes before kickoff (PREDICTION_LOCKOUT = 3600s). Editing = resubmitting on-chain; the user re-pays gas — which on Chiliz is ~$0.05 for a full 18-match batch. Put that number in the UI copy.
  • Every open, submitted match card shows an "Edit prediction" button + live countdown ("Locks in 2h 14m").
  • Edit flow pre-fills the current pick, shows an old → new diff before signing, confirms with a toast.
  • Batch "edit matchday" mode: all changes in one transaction.
  • Telegram posts a last-call reminder ~75 minutes before each kickoff cluster.
  • T&Cs state it plainly: change your mind freely, gas is on you.

UEFA data — the source of truth

UEFA's own undocumented JSON API (the one powering uefa.com), via the MIT-licensed uefa-api npm package.

EndpointUsed for
match.uefa.com/v5/matchesfixtures + results (competitionId=1 = UCL, confirmed; seasonYear mandatory)
match.uefa.com/v5/livescorerelayer fast path — payload includes a change-detection hash
standings.uefa.com/v1/standingsleague table (knockout seeding)
comp.uefa.com/v2/teamsthe 36 participants

Package reality: uefa-api v1.0.2, zero dependencies, dormant since June 2024 → treat as a reference implementation we own: pin it, vendor the types, zod-validate every response, patch our copy if UEFA drifts.

Source-adapter pattern — survive API churn

interface ResultSource {
  id: string;                                  // "uefa-api@1.0.2"
  fixtures(season: string): Promise<Fixture[]>;
  result(ref: string): Promise<MatchResult | null>;  // 90' + total + pens + advancer
  livescore(): Promise<LiveMatch[]>;
  health(): Promise<SourceHealth>;
}

UefaApiSource at launch; FootballDataSource (free tier covers the UCL) specced as fallback. On-chain, an owner-updatable resultSourceRef string declares which feed the oracle relays — swap sources without touching contract logic or frontend.

Fixtures & bracket

  • matches.json keeps the predecessor's shape but is generated from the feed after the 27 Aug draw (+ uefaMatchId, tieId, legNumber). Never hand-authored.
  • Knockout seeding from league positions (top 8 → R16; 9–24 → play-offs) + February draws; the upstream Match.type (FIRST_LEG/SECOND_LEG) maps straight onto our tie model.
  • The predecessor's hard verification gate survives, re-pointed at UEFA: no knockout batch broadcasts unless the numbering-independent bracket check passes.

Official club crests

Primary: football-data.org free tier (crests.football-data.org/{teamId}.png, 10 req/min, cached server-side). Fallback chain (Fanbet's production pattern, never blank): manual override → football-data crest → img.uefa.com team PNG → coloured monogram — implemented as a plain <img onError> swap (not Radix Avatar; see Fanbet's 2026-05-29 incident). Legal note: crests are trademarks — fine for a prototype, needs clearance for a commercial launch.

§8–9

The results oracle — "very little maintenance"

Target: an untouched laptop for an entire matchday leaves the system fully settled.

UEFA API ──▶ Relayer (GitHub Actions, every 5 min on matchdays)
                │  zod-validate → 90' score + flags → idempotency guard
                ▼
     ClPredictor.pushResult(matchId, packed)   [RESULT_ORACLE_ROLE]
                │                      (provisional, 24h dispute window)
                ▼
     auto-finalize ──▶ points computable ──▶ Telegram post + Supabase sync
  • Relayer on GitHub Actions cron (free) — Vercel Hobby crons are daily-only, unusable for match polling; cron-job.org is the documented backup trigger. Every 5 min in matchday windows, hourly otherwise, concurrency.group so runs never overlap, idempotency guard before every submit (Fanbet's proven bot pattern).
  • Dedicated oracle wallet holds only gas, has only RESULT_ORACLE_ROLE; owner key never in CI; owner can rotate the oracle any time.
  • Automates: results (90′ + flags), kickoff updates, knockout fixture generation after draws (behind the verification gate), Supabase sync, Telegram posts.

Corrections — the undo button

  • Results are PROVISIONAL for 24h, then auto-finalize. Admin correctResult() freely inside the window; the relayer also self-corrects if UEFA amends a score. The leaderboard moves immediately, with a ◌ provisional badge (D9) — match night is the engagement moment; Telegram posts carry the same label.
  • Post-finalization corrections require pause() + forceCorrectResult — deliberate friction, loudly evented.
  • Because scoring is computed at claim/freeze time, a pre-payout correction re-scores everyone automatically — no per-user settlements to unwind.
  • Non-football outcomes: mirror UEFA verbatim (D6). Whatever score.regular records is the result — forfeits and green-table 3-0s included (WIN_BY_FORFEIT). The oracle stays perfectly dumb; the T&Cs pre-answer it: "Take it up with Nyon."
  • Wrong match (our mistake, not UEFA's)? voidMatch(). Wrong teams pre-kickoff? setMatchTeams(), predictions preserved.

Breakage detection — assume the unofficial API breaks at the worst moment

  • Schema watch: zod on every response — shape drift raises SOURCE_SCHEMA_CHANGED, never a silent undefined.
  • Staleness watchdog: match finished >2h ago with no result, or zero fixtures on a known matchday → SOURCE_STALE.
  • Alerts: Telegram DM to admin + private ops channel, GitHub Actions failure e-mail as the second wire. Daily "✅ oracle healthy" heartbeat — so silence itself is detectable.
  • Degraded mode: app banners "results delayed"; the old manual admin path survives as the emergency fallback. Recovery = swap the adapter + update resultSourceRef; contract and frontend untouched.

What's left of the admin console: oracle health dashboard, the correction actions above, stage lifecycle (open/close entry, freezeStage), emergencies (pause, oracle rotation, UUPS upgrade). Routine per-match work: none — down from 2 signed txs + a manual feed cross-check per match.

Contract v3 — ChampionzPredictor.sol

Solidity 0.8.24 (Chiliz ceiling, Shanghai EVM), OpenZeppelin UUPS proxy, Hardhat toolchain, keyless Chiliscan verification.

★ Gas: beat the World Cup contract

v2's dominant cost was batchSettleUserPoints — admin-paid loops writing ~20k gas per user per match, O(users × matches). v3 deletes the concept: points are a pure function of (predictions, results), computed at read/claim/freeze time.

Point settlementper-match, per-user storage writes + guard slotsnone — lazy scoring

Also: bit-packed predictions (1 slot) and results (1 slot) · matchday batch submission (1 tx, up to 18 matches) · custom errors · events over storage · bytes3 team codes, no strings in hot paths. Chiliz v2.8.1 (30 Jun 2026) enabled EIP-7702 — batched enter+predict UX is a flagged opportunity, not a dependency.

User gas reality: min gas price 2,501 gwei (EIP-1559, 2,500 base + 1 tip). An 18-match packed batch ≈ 450k gas ≈ 1.1 CHZ ≈ $0.05.

Keys (D5): owner = 0x47103b0FC04c91Ac388eaE3c4f91D038CBfD9CF8 — a single hardware-backed key, never in CI, never hot. Multisig rejected as ceremony for a solo operator; the contract caps owner power structurally instead (on-chain freeze recomputation, pause-gated corrections, 180-day-locked emergency withdrawal, separate low-value oracle key). feeRecipient defaults to the owner wallet.

§16

Security program

★ Cross-model adversarial pentest loop

  1. Design & build the contract with the primary model; full unit + fuzz tests.
  2. Red team with a different model: frozen source + ABI, fresh context, attacker persona, zero design rationale. Severity-ranked findings with PoC sketches.
  3. Loop: designer fixes → red team re-attacks the diff → repeat until two consecutive clean rounds.
  4. Everything logs to SECURITY_FINDINGS.md — the new Audit.MD and future regression checklist.
  • Known-weakness scan: Slither (zero-high gate) + Snyk + npm audit; checklist sweep — reentrancy, oracle manipulation/single-source trust, front-running (plaintext predictions: inherited accepted risk, lockout-mitigated), access control, UUPS pitfalls, unbounded loops (freeze bounded at 20), rounding, signature replay (ERC-1271 path), exact-value enforcement.
  • Past-hack review: prediction-market/staking incident families — oracle-feed manipulation and admin-key compromise → oracle role separation + owner multisig recommendation.
  • Regression baseline: all 18 predecessor audit findings (H-01…L-06) re-checked against v3, incl. the 180-day-locked emergencyWithdraw.
  • Ops: low-value gas-only oracle key in Actions secrets; owner key never in CI; rotation calendar; incident runbook (detect → assess → pause → announce ≤1h → remediate → postmortem).
  • Geo-fencing (D7): copy Fanbet's production edge block verbatim — HTTP 451 for the same 14 jurisdictions (CN, BD, DZ, EG, NP, AF, KP, IQ, IR, AE, ID, VN, QA, SG) + a T&C eligibility clause. An engineering mitigation, explicitly not legal advice.
